MEMBER MASTER — SUPPLEMENTARY AND AUDIT COLUMNS

The columns described here were added to MBRMST after the original conversion and are documented separately because several of them are not carried on the standard extract layouts. MBR_MOTHER_MAIDEN_NAME (CHAR 30, nullable) is captured at account origination as a verbal authentication challenge for telephone service. It is stored on the member master row for operational reasons but is excluded from every extract without exception, is not displayed on any printed report, and is visible only on screen CIF11, which is restricted to the member service supervisor group. The Records Custodian reviews the CIF11 authority list semiannually.

MBR_DRIVERS_LIC_NBR (CHAR 20, nullable) and MBR_DRIVERS_LIC_STATE (CHAR 2, nullable) are populated during identification verification at account opening. Both columns are restricted to the same authority list as MBR_SSN and are retained only for the life of the relationship plus five years, at which point the purge utility blanks them in place rather than deleting the row, so that transaction history remains referentially intact.

MBR_EMPLOYER_NAME (CHAR 40, nullable) and MBR_OCCUPATION_CD (CHAR 4, nullable) support field-of-membership verification. Because eligibility is periodically re-examined by the examiner, these columns are retained for the life of the relationship and are included in the field-of-membership audit extract, which is produced on demand and is not scheduled.

Audit columns are common to all tables in the member complex. MBR_ADD_USER (CHAR 10, NOT NULL) and MBR_ADD_TS (TIMESTAMP, NOT NULL) record the teller or batch identity that created the row. MBR_CHG_USER (CHAR 10, nullable) and MBR_CHG_TS (TIMESTAMP, nullable) record the last maintenance. MBR_CHG_PGM (CHAR 10, nullable) records the program name and is the only reliable means of distinguishing operator maintenance from batch maintenance, since several batch jobs run under a shared identity. Operations has been asked repeatedly to assign distinct identities to the nightly jobs; this has not been done and the program name column remains the workaround.

Three columns are documented here as deprecated. MBR_TELEPHONE_PIN (CHAR 4, nullable) was superseded by the audio response unit's own credential store in the 1997 release; values remain on approximately forty percent of rows and are not maintained. The column is scheduled for blanking at the next release but has not yet been addressed. MBR_SPOUSE_NAME (CHAR 40, nullable) is no longer captured and is not maintained on existing rows; it should not be relied upon for joint ownership determination, which is carried on the ownership cross-reference table. MBR_HOME_FAX (CHAR 10, nullable) is unused.

Extract handling for the supplementary columns is by explicit column list in each extract program. There is no view layer enforcing exclusion, which the Records Custodian has noted as a control weakness in the last two annual reviews. Any new extract request must be reviewed against this document before the program is written, and the reviewer's initials must be recorded on the extract request form retained in Information Systems.
