DATA DICTIONARY — SUBJECT AREA 03, CUSTOMER/MEMBER MASTER
Table CUSTMAST, DB2 UDB v7.2, subsystem DBP1, tablespace TSCUST03
Revision 4.2, effective 01 MAR 2004. Supersedes Rev 4.1 in its entirety.
Content authority: the Records Custodian, Corporate Compliance. Structural authority: the Database Administration group.

The primary key column CUST_KEY_ID is DECIMAL(11,0), NOT NULL, assigned by sequence generator SQCUST at insert and never reused following a purge; the value is meaningless outside the enterprise and is the only customer reference permitted in application logs. LOYALTY_CARD_NBR, CHAR(13), NULL permitted, carries the scannable card credential issued at point of sale and is unique where present; nulls occur for accounts established through the pharmacy counter without a card issue. RX_PATIENT_ID, CHAR(10), NULL permitted, links to the dispensing system and is populated only for records with an active pharmacy relationship; this column is restricted, and read access is granted through RACF group PHRXRD only, provisioned on written request of the store's Pharmacist in Charge or the Privacy Officer.

Name and demographic columns are as follows. CUST_LAST_NAM, VARCHAR(30), NOT NULL. CUST_FRST_NAM, VARCHAR(20), NOT NULL. CUST_MID_INIT, CHAR(1), NULL permitted. CUST_NAM_SFX_CD, CHAR(4), NULL permitted, validated against reference table REFSFX. CUST_BIRTH_DT, DATE, NULL permitted at the master level but required before any pharmacy transaction posts; the trigger TRCUSTB1 rejects downstream dispensing inserts where the column is null. CUST_GENDER_CD, CHAR(1), NULL permitted, values constrained by check constraint CKGEND to the reference domain. CUST_SSN_NBR, CHAR(9), NULL permitted; population is confined to records originating in the third-party billing conversion of 1998 and no interface is authorized to write to this column. It is masked in all screen presentations, excluded from every extract enumerated below, and is scheduled for physical removal under change request CR-2004-0311.

Contact columns are HOME_PHON_NBR CHAR(10) NULL permitted; ALT_PHON_NBR CHAR(10) NULL permitted; EMAIL_ADR_TXT VARCHAR(60) NULL permitted, unvalidated at entry and known to contain a material proportion of unusable entries collected at register; ADDR_LN_1_TXT VARCHAR(40) NULL permitted; ADDR_LN_2_TXT VARCHAR(40) NULL permitted; CITY_NAM VARCHAR(28); STATE_CD CHAR(2); POSTAL_CD CHAR(9); and ADDR_VERIF_STAT_CD CHAR(1), set by the quarterly address hygiene run and not to be overwritten by store personnel.

Control columns CREATE_TS, LAST_MAINT_TS, LAST_MAINT_USER_ID and SRC_STORE_NBR are NOT NULL throughout and are maintained by the application layer; direct SQL update by any party other than the Database Administration group is a reportable exception.

Retention is seven years from LAST_ACTIVITY_DT for the record as a whole, except that CUST_BIRTH_DT, CUST_SSN_NBR and RX_PATIENT_ID are suppressed at the two-year mark by the annual minimization job PGMCUST7 and are recoverable thereafter only from archive tape under dual authorization. Two downstream extracts are authorized: the weekly marketing file XMKT01, which carries CUST_KEY_ID, name, address and POSTAL_CD only, and the monthly benefits reconciliation file XBEN04, which carries CUST_KEY_ID and RX_PATIENT_ID and is transmitted by Connect:Direct to the plan administrator. All other extract requests route to the Privacy Officer for written disposition before development effort is scheduled.
