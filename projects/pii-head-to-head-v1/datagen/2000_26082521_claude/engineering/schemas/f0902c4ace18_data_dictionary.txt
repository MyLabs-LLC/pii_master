MERIDIAN STAFFING GROUP — DATA GOVERNANCE
DATA DICTIONARY EXCERPT / FORM DD-402

1.0  IDENTIFICATION
     1.1  Table ................ PLC.APPLICANT_INTAKE
     1.2  Source Application ... Web intake portal and branch kiosk
     1.3  Version .............. 4.1, effective 22-MAR-2016
     1.4  Completed By ......... the Records Custodian
     1.5  Countersigned ........ the Branch Operations Manager
     1.6  Sensitivity Tier ..... 2, with Tier 3 exceptions noted at 3.2

2.0  COLUMN DEFINITIONS
     2.1  APPLICANT_ID          NUMBER(10)   NOT NULL
          Surrogate key. Retained after promotion to CANDIDATE_ID for lineage.
     2.2  SUBMISSION_CHANNEL    CHAR(3)      NOT NULL
          WEB / KSK / PHN / WLK.
     2.3  APPLICANT_LAST_NAME   VARCHAR2(40) NOT NULL
     2.4  APPLICANT_FIRST_NAME  VARCHAR2(30) NOT NULL
     2.5  DATE_OF_BIRTH         DATE             NULL
          Collected only where a role carries a statutory minimum age.
     2.6  SSN_LAST_FOUR         VARCHAR2(4)      NULL
          Collected for background screening consent only. Full number is never
          captured at intake.
     2.7  DRIVERS_LICENCE_NUM   VARCHAR2(20)     NULL
     2.8  DRIVERS_LICENCE_STATE CHAR(2)          NULL
     2.9  MAILING_ADDRESS_LINE1 VARCHAR2(60)     NULL
     2.10 MAILING_CITY          VARCHAR2(40)     NULL
     2.11 MAILING_STATE         CHAR(2)          NULL
     2.12 MAILING_POSTAL        VARCHAR2(10)     NULL
     2.13 CONTACT_PHONE         VARCHAR2(20)     NULL
     2.14 CONTACT_EMAIL         VARCHAR2(80)     NULL
     2.15 BACKGROUND_CONSENT_FL CHAR(1)      NOT NULL
     2.16 BACKGROUND_ORDER_REF  VARCHAR2(24)     NULL
     2.17 SCREEN_RESULT_CODE    CHAR(2)          NULL
          Adjudication outcome only. No underlying report content is stored.
     2.18 REFERRAL_SOURCE_CODE  VARCHAR2(10)     NULL
     2.19 INTAKE_TS             TIMESTAMP    NOT NULL
     2.20 PROMOTED_FLAG         CHAR(1)      NOT NULL

3.0  ACCESS RESTRICTION
     3.1  Intake rows are visible to branch recruiters through V_INTAKE_QUEUE,
          which suppresses 2.6, 2.7 and 2.8.
     3.2  Columns 2.6 through 2.8 and 2.16 through 2.17 are Tier 3. Direct
          table access is limited to the screening interface account and to the
          Records Custodian. Screening outcomes are discussed verbally with the
          Branch Operations Manager; they are not forwarded by internal mail.
     3.3  Any export request outside the roles above is raised on Form DG-19
          and held for five working days before release.

4.0  RETENTION
     4.1  Unpromoted applications: 2 years from INTAKE_TS, then purged.
     4.2  Promoted applications: retained until the linked candidate record is
          purged, so the two schedules remain aligned.
     4.3  Screening columns (2.16, 2.17): nulled 12 months after adjudication
          regardless of promotion status.
     4.4  Purge suspended where a legal hold is recorded against APPLICANT_ID.

5.0  DOWNSTREAM EXTRACTS
     5.1  Screening vendor interface: outbound carries names, SSN_LAST_FOUR,
          licence columns and the consent flag. Inbound carries only
          BACKGROUND_ORDER_REF and SCREEN_RESULT_CODE.
     5.2  Recruiting funnel reporting: SUBMISSION_CHANNEL, REFERRAL_SOURCE_CODE,
          PROMOTED_FLAG, aggregated by week.
     5.3  No intake column is permitted in the candidate re-engagement mailing
          extract without written approval from the Director of Compliance.
