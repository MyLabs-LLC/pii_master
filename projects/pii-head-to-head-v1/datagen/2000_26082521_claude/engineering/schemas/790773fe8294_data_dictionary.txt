DATA DICTIONARY — GUARDIAN AND HOUSEHOLD CONTACT DOMAIN
Prepared by the Office of Information Management for the Data Governance Committee
Applies to: SIS_PROD, schema sis_contact
Status: approved for the 2021-22 school year

1.0 Table GRD_CONTACT
    1.1 Purpose and grain
        1.1.1 One row per contact person associated with one or more students.
        1.1.2 Association to students is carried in the bridge table STU_GRD_XREF; a contact may serve multiple households.
    1.2 Columns
        1.2.1 GRD_ID — NUMBER(9) — NOT NULL — surrogate key, sequence generated.
        1.2.2 NAME_LAST — VARCHAR2(40) — NOT NULL — restricted.
        1.2.3 NAME_FIRST — VARCHAR2(40) — NOT NULL — restricted.
        1.2.4 RELATIONSHIP_CD — VARCHAR2(4) — NOT NULL — parent, guardian, foster, emergency, other.
        1.2.5 CUSTODY_FLG — CHAR(1) — NOT NULL — default 'N'; when 'Y', release of records requires no further verification.
        1.2.6 COURT_ORDER_FLG — CHAR(1) — NOT NULL — default 'N'; when 'Y', the record is locked to the registrar role and the Records Custodian, and no vendor extract may include the row.
        1.2.7 PHONE_MOBILE — VARCHAR2(20) — NULL — stored unformatted; formatting applied at extract time.
        1.2.8 PHONE_HOME — VARCHAR2(20) — NULL — deprecated for new entry as of 2021-08-01, retained for legacy rows.
        1.2.9 PHONE_WORK — VARCHAR2(20) — NULL.
        1.2.10 EMAIL_PRIMARY — VARCHAR2(80) — NULL — required for portal account creation; uniqueness is not enforced because siblings frequently share one address.
        1.2.11 EMAIL_ALTERNATE — VARCHAR2(80) — NULL.
        1.2.12 PREFERRED_LANGUAGE_CD — VARCHAR2(3) — NOT NULL — default 'ENG'; drives translation routing in the mass notification platform.
        1.2.13 NOTIFY_VOICE_FLG, NOTIFY_SMS_FLG, NOTIFY_EMAIL_FLG — CHAR(1) each — NOT NULL — consent flags; SMS defaults to 'N' pending affirmative opt-in.
        1.2.14 REC_ACTIVE_FLG — CHAR(1) — NOT NULL.
    1.3 Notes
        1.3.1 Contact rows are never hard-deleted during the school year. Deactivation is performed by setting REC_ACTIVE_FLG to 'N' so that the notification audit trail remains intact.
        1.3.2 Duplicate contacts are merged by the enrollment clerk using the merge utility; the surviving GRD_ID is recorded in GRD_MERGE_LOG.

2.0 Table HH_ADDRESS
    2.1 Grain: one row per household address, referenced by both students and contacts.
    2.2 Columns
        2.2.1 HH_ID — NUMBER(9) — NOT NULL.
        2.2.2 ADDR_LINE_1 — VARCHAR2(60) — NOT NULL.
        2.2.3 ADDR_LINE_2 — VARCHAR2(60) — NULL.
        2.2.4 CITY_NAME — VARCHAR2(40) — NOT NULL.
        2.2.5 STATE_CD — CHAR(2) — NOT NULL.
        2.2.6 POSTAL_CD — VARCHAR2(10) — NOT NULL.
        2.2.7 GEOCODE_LAT, GEOCODE_LON — NUMBER(9,6) — NULL — populated by the quarterly geocoding batch; used for attendance boundary validation and bus stop assignment.
        2.2.8 MAIL_SUPPRESS_FLG — CHAR(1) — NOT NULL — default 'N'.
        2.2.9 VERIFIED_DT — DATE — NULL — set at annual residency verification.

3.0 Access restriction
    3.1 Write access is limited to the enrollment clerk and registrar roles at the assigned building.
    3.2 Read access for building administrators is scoped by building code through row-level security.
    3.3 Any bulk export exceeding five hundred rows is logged and reviewed monthly by the Records Custodian.

4.0 Retention
    4.1 Contact and address rows are retained for the duration of enrollment plus three years.
    4.2 Notification consent flags are retained for seven years to support complaint response.

5.0 Downstream extracts
    5.1 Mass notification platform, nightly delta: names, phone columns, email columns, language code, consent flags. Rows with COURT_ORDER_FLG set to 'Y' are excluded at the query level, not at the vendor.
    5.2 Transportation routing system, weekly full load: HH_ID and geocode columns only.
    5.3 Learning management system, term-start load: EMAIL_PRIMARY and student cross-reference only.
