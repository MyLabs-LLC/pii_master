Change note CHG-2021-0177 — mapping rule revision, POD family — effective 2021-04-22

This note records the revision applied to the proof-of-delivery mapping rules ahead of the 22:00 run under job identifier ETL-POD-EVE-0233. The previous rule set carried proof_of_delivery_signature_image through to the warehouse as a stored object reference, on the assumption that the reference itself disclosed nothing. Review by the Data Protection lead concluded that the reference resolves to an image of a person's handwriting and should be treated as personal data in its own right. The field has therefore been moved into the mask stanza of the masking policy and the mapping rule now emits the placeholder literal.

The same revision renames two output columns so that the warehouse names match the source names, removing a long-standing source of confusion during incident work. The column previously written as recipient_name is now written as consignee_full_name, and the column previously written as delivered_to is now written as signatory_name, which is suppressed. Downstream views were updated in the same window and the reporting team confirmed at 21:14Z that nothing was left referencing the old names.

The first run under the revised rules read 96,344 rows and wrote 96,344, with no quarantine. The writer log confirmed the expected shape, for instance: `row=00021 consignee_full_name=[MASKED] signatory_name=<null> proof_of_delivery_signature_image=[MASKED] customer_account_ref=[TOKENIZED]`. A comparison against the preceding evening's output showed the same row count and the same token values for customer_account_ref, which is the determinism check we run after any policy change. The revision is considered settled and no rollback window is being held open.
